## User Creation

Create a new user:

```bash
useradd newusername
```

Two important options:

| Option | Role |
|--------|------|
| `-d /path` | Set a specific *home directory* |
| `-m` | Force **creation** of the *home directory* |
| `-s /bin/bash` | Set the login shell |
| `-G group1,group2` | Add the user to secondary groups at creation |

```bash
useradd -d /home/test -m username
```

> [!TIP]
> On Debian and derivatives, `adduser` is an interactive script built **on top of** `useradd`: it creates the home, copies content from `/etc/skel`, and asks for password and user information.
>
> ```bash
> sudo adduser username
> ```
>
> `useradd` remains the right choice in a **script** (non-interactive, identical behavior everywhere).

## List a User's Groups

List my groups:

```bash
groups
```

List another user's groups:

```bash
groups otheruser
```

For more details (UID, GID, all groups):

```bash
id username
```

## Modify a User

Add a group to a user:

```bash
usermod -aG newgroup username
```

> [!WARNING]
> The `-a` (*append*) is **mandatory** with `-G`. Without it, `usermod -G group username` **replaces** the entire list of the user's secondary groups, removing them from all others — including `sudo`.

Remove a user from a group:

```bash
gpasswd -d username group
```

or on Debian and derivatives:

```bash
deluser username group
```

Other common modifications:

| Command | Effect |
|----------|-------|
| `usermod -l newname oldname` | Rename the user |
| `usermod -s /usr/bin/zsh username` | Change their shell |
| `usermod -L username` | Lock the account |
| `usermod -U username` | Unlock the account |

> [!IMPORTANT]
> Group changes apply only to **new** sessions. The user must log out/in (or run `newgrp group`) for new rights to take effect.

## Delete a User

```bash
userdel username
```

Also delete their *home directory*:

```bash
userdel -r username
```

## List Users on the Machine

```bash
cat /etc/passwd
```

Each line follows this format:

```text
username:x:1001:1001:Comment:/home/username:/bin/bash
    │    │   │    │       │            │            │
   name   │  UID  GID    GECOS        home         shell
         └─ password (the "x" refers to /etc/shadow)
```

> [!NOTE]
> Passwords are **not** in `/etc/passwd` (readable by all) but in `/etc/shadow`, as hashes and readable by root only.
> A user whose shell is `/usr/sbin/nologin` or `/bin/false` is a service account: they cannot open a session.

## Change a Password

Change your own user's password:

```bash
passwd
```

Change another user's password — **as root**:

```bash
passwd username
```

Force a user to change their password on next login:

```bash
passwd -e username
```

## Group Management

Create a group:

```bash
groupadd groupname
```

Delete a group:

```bash
groupdel groupname
```

List groups on the machine:

```bash
cat /etc/group
```

## Switch Users

```bash
su - username
```

The dash (optional) triggers a **login shell**: it loads the target user's full environment and places the terminal in their *home directory*.

| Command | Effect |
|----------|-------|
| `su username`   | Switch users but **keep** current environment and directory |
| `su - username` | Open a proper session, like a real login |

> [!TIP]
> The difference between login shell and interactive shell determines which configuration files are loaded (`~/.profile` vs `~/.bashrc`). This is the subject of [chapter 10](10_shell_config.md).

## The root User (Admin)

The `root` account is the machine's administrator. Everything concerning system management (adding users, installing packages, configuring services…) must be executed as root.

> [!CAUTION]
> **Stay root for the shortest time possible.**
> The principle is to do a maximum of things with minimum rights: a typo as root can destroy the system, and an open root shell is a wide-open door.

Two possible methods:

### 1. Execute *one* command as root — **strongly recommended**

```bash
sudo command
```

I can also specify the user whose identity I want to assume:

```bash
sudo -u username command
```

### 2. Switch users — reserve for administration sessions

```bash
su
```

```bash
su root
```

```bash
sudo su -
```

> [!NOTE]
> On Ubuntu, the root account has no password by default: `su` fails, you must use `sudo`.
> Fine-grained configuration of who can do what via `sudo` is covered in [chapter 05 · Security](05_securite.md#sudosudoers).

### Exit a Session

```bash
exit
```

or the shortcut `CTRL + D`.

## Summary

| Command | Role |
|----------|------|
| `useradd` / `adduser` | Create a user |
| `userdel -r` | Delete a user and their home |
| `usermod -aG group user` | Add to a group |
| `gpasswd -d user group` | Remove from a group |
| `groupadd` / `groupdel` | Create / delete a group |
| `groups` / `id` | See a user's groups |
| `passwd` | Change a password |
| `su -` | Switch users |
| `sudo` | Execute a single command as root |
| `/etc/passwd` · `/etc/group` · `/etc/shadow` | Accounts · groups · passwords |
